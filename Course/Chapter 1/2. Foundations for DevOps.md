# DevOps Practices

Transitioning to DevOps requires a change in culture and mindset. At its simplest, DevOps is about removing the barriers between two traditionally siloed teams. It achieves this by providing tools and practices that improve the delivery of software releases. In some organizations, there may not even be separate teams; engineers may perform both roles. DevOps also helps shorten the feedback loop and encourages continuous experimentation.

With DevOps, the two functions work together to optimize developer productivity and operational reliability. They communicate frequently, increase efficiency, and improve quality. They take full ownership of the services they deliver, often beyond the traditional scope of their roles, by considering the customer’s needs and how they can contribute to solving them. Quality assurance and security teams may also become tightly integrated with these teams.

Regardless of their organizational structure, companies using a DevOps model have teams that view the entire development and infrastructure lifecycle as part of their responsibility. The underlying principle of DevOps is: people over process over tools. This means relationships are the most important factor, followed by process, and then by tools.

## Continuous Integration and Continuous Delivery (CI/CD)

CI and CD are processes in a pipeline that support the software delivery lifecycle. As discussed earlier, communication and collaboration are essential to DevOps. Frequent communication and the opportunity for customers to provide feedback on changes are how DevOps is connected to CI/CD.

- Continuous integration (CI) is the process in which developers integrate source code continuously and automate the build and test phases.
- Continuous delivery (CD) extends CI by including provisioning, deployment, and post-deployment testing or monitoring.

When the following CD best practices are applied, software can be released to production at any time:

- Code changes are committed to the repository and built frequently.
- Builds are deployed to test environments and checked using automated and manual tests.
- Builds that pass rigorous validation are rapidly deployed to staging or production environments.

A robust continuous delivery pipeline also does the following:

- Automates the provisioning of infrastructure for testing and production environments.
- Enables monitoring and management of test and production environments.
- Supports continuous deployment as a fully automated end-to-end process.

The goal of DevOps is to follow a continuous delivery model that is repeatable, reliable, stable, resilient, and secure, while improving operational efficiency. But how useful is a DevOps approach if the teams involved still work in silos?

Relationships across teams are vital: without cross-team communication and collaboration, processes are likely to fail. Teams must collaborate with each other and stay involved throughout the development and delivery process. All technical team members should have experience with the processes and tools involved in the development pipeline.

### Continuous Integration

Continuous integration is a software development practice in which developers regularly merge their code changes into a central repository, after which automated builds and tests are run.

### Continuous Delivery

Continuous delivery is a software development practice in which code changes are automatically built, tested, and prepared for release to production. It expands on continuous integration by deploying all code changes to a testing or production environment after the build stage.

### Microservices

Microservices is a design approach that builds a single application as a set of small, independent services.

### Infrastructure as Code

Infrastructure as code is a practice in which infrastructure is provisioned and managed using code and software development techniques, such as version control and continuous integration.

### Monitoring and Logging

Organizations monitor metrics and logs to understand how application and infrastructure performance affects the user experience.

### Communication and Collaboration

Increased communication and collaboration are key cultural aspects of DevOps. DevOps tooling and automation of the software delivery process help bring together the workflows and responsibilities of development and operations.

## AWS Services for Different Practices

Now that you understand the core practices, take a look at the AWS services that support each one. AWS provides services designed to help organizations adopt DevOps practices at scale. These tools automate manual tasks, help teams manage complex environments, and keep engineers in control of the velocity enabled by DevOps.

### Version Control

- AWS CodeCommit: A version control service that enables you to privately store and manage Git repositories in the AWS Cloud.

### CI/CD

- AWS CodePipeline: A continuous delivery service that lets you model, visualize, and automate the steps required to release software.
- AWS CodeBuild: A fully managed build service that compiles source code, runs unit tests, and produces deployable artifacts.
- AWS CodeDeploy: A deployment service that automates application deployment to instances and updates applications as needed.
- AWS CodeStar: A service that helps you quickly develop, build, and deploy applications on AWS.
- AWS Cloud9: A cloud-based integrated development environment (IDE) for writing, running, and debugging code.

### Microservices

- Amazon Elastic Container Service (Amazon ECS): A highly scalable container management service for running, stopping, and managing Docker containers on a cluster of Amazon EC2 instances.
- AWS Lambda: A serverless compute service that runs code without requiring you to provision or manage servers.

### Infrastructure as Code

- AWS CloudFormation: A service for creating and provisioning AWS infrastructure deployments predictably and repeatedly.
- AWS Elastic Beanstalk: A service for deploying and managing applications in the AWS Cloud without managing the underlying infrastructure.
- AWS OpsWorks: A service for creating and managing stacks and applications, including provisioning AWS resources and deploying applications.
- AWS Systems Manager: A unified interface for operational data and automation across AWS resources.
- AWS Config: A service that provides visibility into AWS resource configurations and their changes over time.

### Monitoring and Logging

- Amazon CloudWatch: A monitoring service for AWS resources and applications in real time.
- AWS CloudTrail: A service that records AWS API calls and provides a history of account activity.
- AWS X-Ray: A service for tracing application requests and analyzing distributed application behavior.
- AWS App Mesh: A service for monitoring and controlling microservices running on AWS.

### Security

- AWS Identity and Access Management (AWS IAM): A service for securely controlling access to AWS resources and services.
- Amazon GuardDuty: A continuous security monitoring service that detects unauthorized or malicious activity in your AWS environment.
- AWS Key Management Service (AWS KMS): A service for creating and managing encryption keys for cloud workloads.
- Amazon Inspector: A security assessment service that identifies vulnerabilities and compliance issues in AWS resources.
- AWS Security Hub: A security service that provides a comprehensive view of the security state of AWS resources across accounts and services.
